CloudStore — aplicação de três camadas com Docker

Uma loja online implantada em contêineres, isolando frontend, API e banco de dados. Só o frontend vai para a “rua”: a API e o banco vivem numa rede interna, sem nenhuma porta publicada — o equivalente local de sub-redes pública e privada na nuvem.

Ver a vitrine Repositório no GitHub Pipeline CI/CD

A arquitetura

Quatro contêineres numa única rede Docker. A regra que organiza tudo: só publica porta quem precisa receber tráfego de fora.

Sub-rede pública — acessível pelo host
web nginx:alpine — vitrine + proxy reverso 8080 → 80 publicada
minio (console) Console de administração do armazenamento de objetos 9001 publicada
▼   o nginx encaminha /api/ por dentro da rede   ▼
Sub-rede privada — sem rota vinda do host
api traefik/whoami — responde quem atendeu sem ports:
banco redis:alpine + volume dados-banco sem ports:
minio (API S3) Porta 9000 + volume dados-objetos sem ports:

Como rodar

Requer Docker com Compose v2. Tudo sobe com um comando.

git clone https://github.com/lucasetculbra/cloudstore-docker.git
cd cloudstore-docker/loja-docker
docker compose up -d
docker compose ps
EndereçoO que é
http://localhost:8080vitrine da loja
http://localhost:8080/api/API interna, servida pelo proxy reverso
http://localhost:9001console do MinIO (admin / admin12345)

O pipeline de CI/CD

Quatro etapas encadeadas no GitHub Actions — esta página é publicada pela última delas. A mais interessante é a primeira: ela transforma a regra de segurança da arquitetura num teste automático.

1 validar

Valida o compose e aplica policy as code: o build falha se a api ou o banco ganharem ports:, ou se o MinIO publicar algo além da 9001.

2 testar

Sobe a stack inteira no runner e roda 15 asserções que cobrem as Tarefas 2 a 8 — incluindo persistência do volume e o teste de isolamento de falhas.

3 publicar

Empacota a vitrine numa imagem e envia para o GitHub Container Registry, com tag latest e tag do SHA do commit — o que torna o deploy reversível.

4 paginas

Monta e publica esta página no GitHub Pages, junto com a galeria de evidências e o espelho estático da vitrine. Se o Pages ainda não estiver habilitado, avisa e se encerra sem quebrar o pipeline.

Sobre esta página

A vitrine aqui é uma cópia estática. O GitHub Pages serve apenas arquivos — não há Nginx, contêiner de API nem Redis por trás dele. Por isso a rota /api/ não funciona nesta hospedagem: ela depende do proxy reverso e da rede interna do Docker, que só existem quando a stack está rodando com docker compose up -d. É justamente a diferença entre servir um arquivo e operar uma aplicação de várias camadas.
